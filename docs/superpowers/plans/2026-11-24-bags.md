# Bags and places that hold many pieces: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native for T1–T5, which share one data model; T6's web part is mechanical and may go to a subagent). Steps use checkbox syntax.

**Goal:** the hand becomes the bag `HAND`; places off the board (bags) and map places with a capacity hold counts of pieces; `MOVE`/`PLACE`/`REMOVE`, `COUNT` and `FOR_EACH` speak of them; Kalah plays from these blocks.

**Architecture:** one `holders: IdMap<Position, Holder>` store beside `pieces`; a place is a holder if it is a bag or a map place with capacity above 1. Ways record holder changes next to board changes; views read both. No new effect kinds.

**Tech Stack:** Rust engine/session/wasm; React web board (T6).

**Spec:** `docs/superpowers/specs/2026-11-24-bags-design.md` (read it with the route doc rule: anything from general blocks is built from them).

## Global Constraints

- Shogi and Crazyhouse play exactly as before (`catalogue_counts` unchanged; Shogi/Crazyhouse tests unchanged but for syntax).
- Grid games within 5% of `main` (`ab.sh`, chess/Shogi/Go, three alternating runs); the holder store is empty for them and costs one emptiness check.
- Old saved games load: a saved `hand` becomes the bags `HAND@PLAYER`.
- Reading a spec refuses what it does not know: old `hand`, `hand_enabled`, `removed_to` with `hand`; a holder where it cannot work; `@` in names; a `FOLLOW` along a link that leads to several places.
- Engine clippy no worse than `main` (12 warnings lib); `indexing_slicing`/`expect_used` denied outside tests.
- New names are placeholders (see the design); keep them in one place each so a rename is cheap.

## Review Focus

- A way that would pass a capacity or take more than a holder holds is not offered (T3).
- A shared bag's pieces are nobody's; a piece moved out of one is the mover's (T3).
- `FOLLOW` going round more than once, skipping the other player's store, with 0 steps (T4).
- A saved game from before the change (hand in `state.hand`) loads and plays on (T2).
- Two holders with the same name; `@` in a name (T1).
